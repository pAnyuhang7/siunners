# Momo 桌宠工单

## MVP 范围

目标平台为 Windows。AI 通过在线 API 提供；客户端本地运行桌宠界面、权限判断和工具连接。每项需求均以可观察的用户行为验收。

## 工单

### MOMO-001 项目骨架与安全边界

- 状态：已完成
- 交付：Electron + React + TypeScript 项目；主/渲染进程隔离；窄范围 preload API；开发与构建命令。
- 验收：应用主进程启用 `contextIsolation`、禁用 `nodeIntegration`；项目可通过类型检查和生产构建。

### MOMO-002 桌宠和聊天界面

- 状态：已完成
- 交付：透明无边框置顶窗口、桌宠形象、聊天记录、输入和发送、设置入口、系统托盘。
- 验收：启动后显示桌宠；可拖动窗口、提交消息、查看会话内回复；关闭按钮行为明确。

### MOMO-003 在线模型与凭据设置

- 状态：已完成
- 交付：docode OpenAI Chat Completions 兼容请求、模型设置、加密凭据保存、明确的错误提示。
- 验收：缺少密钥时打开配置提示；有效配置可得到在线模型回复；密钥经 IPC 交给主进程加密落盘，不进入聊天记录或日志。

### MOMO-004 受控应用启动工具

- 状态：确认/取消已实测；实际启动留待用户确认
- 交付：模型可请求打开固定应用清单中的应用；桌宠展示确认/取消操作卡片。
- 验收：未确认不会启动程序；确认仅启动清单内程序；模型不能指定命令、路径或参数。

### MOMO-005 语音交互

- 状态：已实现；真实麦克风与在线识别/播报留待用户实测
- 交付：点击说话（再次点击或 60 秒自动结束）、docode OpenAI 兼容语音识别（默认模型 whisper-1）转文字进入对话、语音播报开关（默认模型 tts-1）与播放；麦克风权限仅授予受信窗口；唤醒词另行评估。
- 验收：录音与播报音频大小受限且仅经主进程转发；密钥不进入渲染进程；识别文本复用既有对话校验与发送链路；未配置密钥时提示先设置。

### MOMO-006 智能家居

- 状态：后续
- 交付：Home Assistant 连接器、设备清单和逐项授权。

### MOMO-007 实体桌宠网关

- 状态：后续
- 交付：MQTT/WebSocket 设备协议和 ESP32 原型；复用工具权限策略。

### MOMO-008 情绪字段与表情联动

- 状态：已排期（调研见 [RESEARCH.md](RESEARCH.md)）
- 交付：模型回复附带 emotion 字段，驱动桌宠表情与动作变化。

### MOMO-009 流式输出

- 状态：已排期（调研见 [RESEARCH.md](RESEARCH.md)）
- 交付：聊天回复流式渲染，降低感知延迟；确认卡片和语音播报适配流式时序。

### MOMO-010 自定义 API 端点

- 状态：已完成
- 交付：设置页可自定义 API 请求地址（OpenAI 兼容，http/https，含本地服务），默认 docode；聊天与语音请求均跟随该地址；地址格式校验，异常落盘值回退默认。
- 验收：留空恢复默认 docode.cc/v1；本地地址（如 Ollama http://127.0.0.1:11434/v1）可保存并生效；含账号密码、查询参数或非 http(s) 的地址被拒绝。

### MOMO-011 桌宠形态重构

- 状态：已完成
- 交付：桌宠以 212×236 透明置顶窗口常驻桌面（默认右下角，可拖动，宠物命中区外点击穿透）；单击桌宠在旁边唤出/收起聊天窗口；聊天窗口不再常驻，仍保留托盘、语音与设置能力。
- 验收：桌宠窗口透明区域不挡桌面点击；拖动桌宠后聊天窗口跟随其侧弹出；聊天窗口关闭按钮仅收起窗口，退出仍走托盘。

### MOMO-012 桌宠自主漫游

- 状态：后续
- 交付：桌宠沿桌面边缘与屏幕底部行走、待机动作；基于 MOMO-011 的透明窗口实现。

### MOMO-013 Anthropic 协议适配

- 状态：已排期
- 交付：支持 Anthropic Messages 协议端点（如智谱 `/api/anthropic`），按地址或手动选择切换 OpenAI / Anthropic 两种请求格式；工具调用映射到 Anthropic tool_use 块。

## 当前验收记录

- 9 项单元测试、TypeScript 检查和 Vite 生产构建通过；模拟测试覆盖普通回复、应用工具往返、加密保存和 401 错误处理。
- docode 真实聊天请求成功，模型返回“你好，Momo！”。
- “请打开记事本”真实请求返回 `notepad` 白名单确认；桌宠确认卡片显示正常，取消后状态显示已取消，应用未启动。
- 应用启动函数通过白名单和空参数单测；本次没有替用户确认启动记事本。实际确认启动留待用户在桌宠卡片中操作。
- API 使用 `https://docode.cc/v1/chat/completions`，通过 `Authorization: Bearer` 传递 Key；Key 已由桌宠设置 IPC 加密保存，未写入工单或命令行。
- 17 项单元测试、TypeScript 检查和 Vite 生产构建通过；语音测试覆盖识别往返、超限/无效录音拦截、401 错误映射、播报音频返回与输入截断。
- 语音链路由主进程请求 docode `/v1/audio/transcriptions`（whisper-1）与 `/v1/audio/speech`（tts-1），录音与播报音频不落盘；真实麦克风识别与播报留待用户在应用中实测。
